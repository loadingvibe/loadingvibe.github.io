# 本地写作、预览与发布

`Blog/` 是网站唯一的作者内容源。可以直接把已有笔记放进这个目录，也可以边写边看网站上的实际阅读效果。

## 最快开始

1. 运行 `npm run dev`，打开终端显示的本地地址（通常是 `http://localhost:4321`）。
2. 在 `Blog/` 中新建 `.md`、`.markdown` 或 `.txt` 文件，直接写正文并保存。
3. 从网站的博客入口或阅读页侧栏打开新笔记。每次保存后页面会更新；增加、重命名和删除文件也会更新目录。
4. 准备上线时运行 `npm run build` 和 `npm run check`，再提交并推送到 `main`。

最小笔记不需要元数据：

```md
# 初识数据类型

今天学习了字符串、整数和布尔值。

## 我的例子

正文……
```

文件名和目录支持中文、英文、空格及多层嵌套。例如 `Blog/Python learning/03-初识数据类型.markdown` 或 `Blog/知识库/数学/学习记录.txt`。这三种扩展名都按 Markdown 语法渲染；纯文本也可以直接阅读。Word、PDF 和图片文件不作为文章解析，需要时可作为附件链接。

`README` 文档、以 `_` 或 `.` 开头的文件或目录，以及 `.assets` 目录中的文本不会作为文章发布。资源目录仍可存放正文引用的图片。

## 可选元数据与自动补全

所有字段均可省略。系统会按以下方式补全：

- 标题：优先使用元数据，其次正文中第一个标题，最后使用文件名。
- 摘要：从正文提取文字；空白文章使用标题生成简短摘要。
- 地址：从文件相对路径生成，去掉扩展名；中文保留，英文转为小写，空格和不适合作为地址的符号会规范化。
- 编号：按源文件路径生成独立的 F 编号，不需要手工寻找下一个编号。
- 分类：默认「笔记」；放在 `朋友圈/` 下默认「生活」，放在 `收藏/` 下默认「收藏」。
- 创建时间：优先读取 `created`、`createdAt` 或 `创建时间`，其次使用文章日期或文件路径日期，再使用 Git 首次加入记录，最后使用文件创建时间。修改时间不参与排序；Git 记录会跟随文件重命名，避免已有文章移动后改变顺序。
- 日期：未填写时使用路径中的日期或自动取得的创建时间，因此直接写正文的笔记也有日期。
- 草稿和精选：默认关闭。

需要固定地址或补充信息时，在文件最前面加入 frontmatter。原有完整模板仍然有效，也可以只写需要的字段。

YAML（使用 `---` 围起）：

```md
---
标题: 初识数据类型
slug: python/初识数据类型
date: 2026-10-04
分类: 学习笔记
标签: Python，数据类型
draft: true
---

## 字符串

正文……
```

JSON（同样使用 `---` 围起）：

```md
---
{
  "title": "Data types",
  "slug": "python/data-types",
  "tags": ["Python", "notes"],
  "draft": false
}
---

正文……
```

TOML（使用 `+++` 围起）：

```md
+++
title = "初识数据类型"
slug = "python/初识数据类型"
tags = ["Python", "笔记"]
draft = true
+++

正文……
```

## 字段与输入格式

| 字段 | 兼容的别名 | 用途与格式 |
| --- | --- | --- |
| `title` | `标题`、`name` | 文章标题 |
| `slug` | `网址`、`url`、`permalink` | 稳定公开地址，支持中文、英文和多段路径 |
| `catalogNo` | `编号`、`catalog`、`id` | 正文编号；已有文章建议保留原值，如 `F-004` |
| `date` | `日期`、`pubDate`、`published`、`发布时间` | 文章日期；未单独指定创建时间时也用于排序 |
| `createdAt` | `created`、`创建时间` | 创建时间；决定门类内从新到旧的顺序 |
| `summary` | `摘要`、`description`、`excerpt` | 搜索、页面描述及 RSS 摘要 |
| `category` | `分类`、`categories` | 自定义分类；数组使用第一个值 |
| `tags` | `标签`、`keywords` | 标签数组或分隔字符串 |
| `draft` | `草稿` | 本地可预览，正式构建时排除 |
| `featured` | `精选`、`推荐` | 是否作为精选文章 |
| `updated` | `更新日期`、`updatedAt`、`modified`、`lastmod` | 更新日期 |
| `cover` | `封面`、`image` | 封面图片路径或完整网址 |
| `aliases` | `alias`、`别名` | 旧 blog 相对路径，生成到当前地址的跳转 |
| `status` | `状态` | `draft`、`private`、`草稿` 或 `私密` 时视为草稿 |

标签和别名支持数组，也支持逗号、中文逗号、分号、换行或 `|` 分隔的字符串。重复或空白项会去除。正文数据中其他字段不会导致构建失败。

日期支持 `2026-10-04`、`2026/10/04`、`2026年10月4日`、完整日期时间以及 Unix 秒或毫秒时间戳。单独的年月日按北京时间解释；建议使用 `YYYY-MM-DD` 或带时区的 ISO 日期时间，避免歧义。无法识别的日期会给出提示并省略，不会阻止阅读。

布尔值支持 `true` / `false`、`yes` / `no`、`on` / `off`、`1` / `0` 和 `是` / `否`。建议写 `draft: true` 或 `draft: false`；无法识别的非空草稿值会保守地作为草稿处理。

写到一半的 frontmatter，例如 YAML 数组尚未闭合或缺少结束分隔线，会恢复能识别的字段并给出作者提示。本地仍可预览，这类文件会暂时视为草稿，修正语法后才进入正式发布。

## 地址、编号与独立文章

显式设置 `slug: python/初识数据类型` 会生成 `/blog/python/初识数据类型/`。中文在浏览器地址及链接中可能显示为百分号编码，两种显示指向同一个页面。

没有填写 `slug` 时，地址跟随源文件路径。因此，已公开的文章如果需要移动或重命名文件，建议先填写原地址作为 `slug`。需要更换公开地址时，把旧地址加入 `aliases`，例如：

```yaml
slug: python/data-types
aliases:
  - Python-learning/03-初识数据类型
```

每个源文件始终是一篇独立文章，不比较正文是否相同，也不会因为正文相同就合并或删除。

重复的 `slug` 按源路径排序处理：第一篇保留地址，后续文章优先使用自己的源路径，仍有冲突时追加短哈希。缺失或重复的编号会生成独立 F 编号。冲突会在本地作者提示中说明；正式发布前建议填写稳定且独立的 `slug` 和 `catalogNo`。公开文章的永久编号应继续保留。

文章正文地址优先于旧地址跳转。某个 `aliases` 已被其他文章正文或旧地址使用时，会跳过该跳转并提示，避免跳到错误文章。

## 侧栏与草稿预览

侧栏自动读取 `Blog/` 下的最外层文件夹，并使用文件夹的原名作为门类。例如 `Blog/2026年知识库/` 显示「2026年知识库」，`Blog/朋友圈/` 显示「朋友圈」。新建文件夹即可增加门类，重命名或删除文件夹也会同步更新；嵌套目录中的文章归入最外层门类。`category` 仍可用于文章元数据，但不会改变文件夹门类。

名称中包含「知识库」的门类使用书本图标，「朋友圈」使用人物图标，其他门类使用文件夹图标。以 `_` 或 `.` 开头的目录及 `.assets` 资源目录不生成门类。直接放在 `Blog/` 根目录的文章归入「未分类」，该门类只在需要时出现。

空文件夹也会显示；若要通过 Git 提交并部署空门类，请放一个 `README.md` 或 `.gitkeep`。Git 不记录空文件夹，这些占位文件不会发布成文章。

各组按文章创建时间从新到旧列出；时间相同时按源文件路径的自然顺序稳定排序，例如 `笔记2` 排在 `笔记10` 前。侧栏显示文章列表，不展开源文件的子目录。修改正文不会让文章重新排到最前；需要固定时间时，在 frontmatter 中填写 `created: 2026-10-04T10:30:00+08:00`。

文章页主标题自动使用 `public/assets/blog/title-icons/` 中的彩色 SVG 图标。所有已发布文章按创建时间从早到晚依次使用：极简台灯、唱片机、茶杯、盆栽、画框、窗户、小沙发、小猫猫、叶子台灯、书架、收音机、吊篮盆栽、置物架、沙发组合；第 15 篇从极简台灯开始下一个循环。时间相同时按源文件路径排序。草稿在本地预览中排在已发布文章之后分配图标，不会改变已发布文章的图标；删除文章或调整创建时间后会根据新顺序重新分配。

`npm run dev` 包含草稿，并显示草稿状态、源文件和元数据提示。`npm run build` 的正式产物排除草稿正文、旧地址跳转、侧栏、RSS 和 sitemap。`npm run preview` 读取已构建的 `dist/`，不会实时读取写作文件；边写边看应使用 `npm run dev`。

## Markdown、目录与大纲

- 标题、列表、引用、链接、表格和代码块按 Markdown 渲染。
- 正文中的 H1–H6 标题都会进入右侧大纲。
- 未写元数据时，可以直接以 `# 文章标题` 开始；填写了 `title` 时，通常从 `## 第一节` 开始。
- 行内数学公式使用 `$E = mc^2$`，独立公式使用两对美元符号。

## 笔记之间的链接

可以按源文件位置写相对链接。站点会找到目标笔记，并转换成它实际使用的公开地址，因此目标填写了自定义 `slug` 或发生了地址避让时，链接仍指向正确文章。

```md
[下一篇](./04-数据类型.md)
[另一目录的笔记](../数学/学习记录.markdown#例子)
[带空格的笔记](<./English note.txt#examples>)
```

兼容 `.md`、`.markdown`、`.txt`、中文目录、空格和嵌套路径。查询参数及 `#锚点` 会保留；含空格的标准 Markdown 地址请用 `<...>` 围起。粘贴的 HTML `<a href="../笔记.md">` 也会转换。

Obsidian 的双链也可以直接使用：

```md
[[学习记录]]
[[数学/学习记录#例子|看这个例子]]
[[./English note|继续阅读]]
```

不带目录的双链仅在该文件名对应唯一笔记时转换。存在同名笔记时，补上目录或 `./` 相对路径；找不到目标或仍有歧义时保留原文，方便写作时先记下待补的链接。双链中的标题锚点会按网站大纲规则生成，显示名称可以通过 `|` 指定。

外部网址、以 `/` 开头的网站地址和代码块中的示例保持原样。正式构建不会把指向草稿的相对链接转换成公开文章地址；本地开发中可以正常跳转预览。

## 图片与附件

可以继续使用笔记软件导出的相对图片路径：

```md
![说明](./03-初识数据类型.assets/图片.png)
```

也可以把静态资源放在 `public/assets/blog/` 下，使用网站根路径：

```text
public/assets/blog/my-note/diagram.webp
public/assets/blog/my-note/reference.pdf
```

```md
![图片的有意义替代文本](/assets/blog/my-note/diagram.webp)
[下载参考资料](/assets/blog/my-note/reference.pdf)
```

`public/` 不出现在 URL 中。外部 `https://` 图片和链接也可使用。正文图片保持原始宽高比：大图等比例缩小，小图不放大。

## 检查与自动上线

```bash
npm run build
npm run check
git add Blog/ public/
git commit -m "content: publish a new note"
git push origin main
```

保存文件会实时更新本地网站；上传公开网站需要提交并推送。`git push origin main` 后，`.github/workflows/deploy-pages.yml` 会自动安装依赖、构建、检查，成功后更新 `gh-pages`。网站访客不能在浏览器中发布或修改仓库文章。

`npm run check` 读取现有 `dist/`，核验正文页面、目录、RSS、sitemap、草稿排除及图片比例，因此要先运行构建。

博客页尾的 `LAST BUILD` 显示当前发布版本的部署构建时间（北京时间）。工作流在构建前固定 `SITE_DEPLOYMENT_BUILD_TIME`，同一时间随页面保存到 `/deployment-build.json`。本地构建读取已获取的 `origin/gh-pages` 发布记录；执行 `git fetch origin gh-pages` 后重启开发服务器或重新构建即可刷新。没有部署记录时显示「尚无部署记录」。

## 管理与删除

本地作者工具显示文章源文件，并提供该文件在 GitHub 上的查看和删除确认链接。链接保留真实扩展名，并对中英文目录正确编码。实际删除由 GitHub 登录、仓库权限和最终提交确认控制，网站不会直接删除文件。

在本地删除文章后，开发目录会立即更新；提交并推送删除操作后，自动部署会移除公开页面。只想暂时下线时，可以设置 `draft: true`。

公开仓库中的草稿源码仍可见。真正私密的本地内容应放在根目录 `.private-drafts/`；该目录已被 `.gitignore` 排除，也不会被网站读取。
